## 0. Как отвечать на короткие вопросы вроде «а метод?»

Такие вопросы короткие и намекают на конкретную конструкцию. Что за ними стоит:

| Она говорит | Она имеет в виду | Что показать и сказать |
|---|---|---|
| «а метод?» | есть ли `override` | метод объявлен `virtual` или `abstract` в базе, в наследнике переписан через `override` |
| «а конструктор?» | какие конструкторы и как вызывается базовый | конструктор без параметров, с параметрами, `: base(...)`, `: this(...)` |
| «а свойства?» | `get` и `set`, проверка | свойство с `set`, где бросается исключение при неверном значении |
| «а статика?» | `static` поле, метод, конструктор | одно значение на весь класс, вызов через имя класса |
| «а абстрактный?» | `abstract class` | объект не создать, есть методы без тела, наследники обязаны их написать |
| «а интерфейс?» | `IEnumerable`, `IEquatable` | класс обещает набор методов, мы их реализуем |
| «а ошибки?» | `try`, `catch`, `finally`, `throw` | где ловим, что бросаем, что выполняется всегда |

Шаблон ответа на «а метод?»:

> «Метод объявлен в базовом классе как `abstract` (или `virtual`). В производном классе я его переопределил через `override`. Поэтому через ссылку базового типа выполняется версия реального типа объекта, это полиморфизм».

Если спросят «почему не `new`?»: `new` скрывает метод, а не переопределяет. Вызов через базовую ссылку выполнил бы версию базы, полиморфизма не было бы.

## 1. Словарик C#: что значат непонятные слова и знаки

Эти слова повторяются в разных лабах. Если встретил незнакомое, ищи здесь.

| Слово или знак | Простыми словами |
|---|---|
| `namespace Lab03;` | «папка» для классов проекта, чтобы имена не путались |
| `using Lab03;` | подключить эту «папку», чтобы писать `Car` вместо `Lab03.Car` |
| `public` | доступно всем |
| `private` | доступно только внутри этого класса |
| `protected` | доступно этому классу и наследникам |
| `static` | принадлежит классу, а не объекту: одно значение на весь класс, вызывается как `Класс.Метод()` |
| `_head`, `_items` | подчеркивание в начале это просто привычка: так называют закрытые поля класса. На работу не влияет |
| `?` после типа (`TransportNode?`) | «может быть пустым (`null`)» |
| `=>` в свойстве (`Count => _items.Length`) | короткая запись «только чтение, значение вычисляется так» |
| `=>` в лямбде (`(a, b) => a - b`) | маленькая безымянная функция: слева параметры, справа результат |
| `{ get; }` | свойство только для чтения, значение задается в конструкторе |
| `{ get; set; }` | свойство для чтения и записи |
| `class A : B` | класс A наследует класс B |
| `base(...)` | вызвать конструктор или метод родителя |
| `this(...)` | вызвать другой конструктор этого же класса |
| `abstract` | у метода или свойства нет тела, наследник обязан написать. Класс с `abstract` нельзя создать через `new` |
| `virtual` | у метода есть тело, но наследник может его заменить |
| `override` | наследник заменяет `virtual` или `abstract` метод родителя |
| `sealed` | запрет наследоваться от этого класса («бесплодный» класс) |
| `new Car(...)` | создать объект |
| `new(...)` | то же, тип компилятор берет слева (`Car c = new(...)`) |
| `<T>` | «любой тип», подставляется при использовании: `CVector<int>` |
| `where T : ...` | ограничение: какие типы можно подставить вместо `T` |
| `IEnumerable<T>` | интерфейс «можно перебирать через `foreach`» |
| `yield return` | отдать следующий элемент и приостановиться (так пишут итераторы) |
| `is` | проверить реальный тип объекта: `x is Train t` |
| `ref` | передать переменную «как есть», метод может ее изменить |
| `out` | метод обязан сам присвоить значение и вернуть его через параметр |
| `try / catch / finally` | `try` опасный код, `catch` реакция на ошибку, `finally` выполняется всегда |
| `throw` | бросить исключение (сообщить об ошибке) |
| `using (...)` или `using var` | автоматически закрыть файл или ресурс после блока |
| `~Класс()` | финализатор (аналог деструктора), вызывается сборщиком мусора |
| `this[int i]` | индексатор: позволяет писать `объект[2]` |

6. *Какие у тебя конструкторы?* Пустой, по размеру, из последовательности, копирования (независимая копия массива).

### Лаба 6. Шаблоны (`Lab06`)

## 4. Общие вопросы по C#

**Конструкторы**
- *Какие бывают?* По умолчанию (если своих нет, создает компилятор), с параметрами, копирования (в C# пишется вручную), статический, `protected` у абстрактных классов.
- *Что выполняется первым?* Сначала конструктор базового класса, потом производного. Цепочки `: this(...)` и `: base(...)`.
- *Если у базы нет конструктора без параметров?* Наследник обязан явно вызвать нужный через `base(...)`.

**`virtual`, `abstract`, `override`, `sealed`, `new`**
- `virtual`: можно переопределить. `abstract`: нужно переопределить, тела нет. `override`: переопределение. `sealed class`: запрет наследования. `new`: скрытие, не полиморфизм.

**Абстрактный класс и интерфейс**
- Абстрактный класс: одно наследование, хранит состояние и готовые методы, есть конструктор. Интерфейс: можно реализовать несколько, только контракт.

**Свойства и индексаторы**
- Свойство: `get` и `set`, можно проверять значения. `{ get; }` только чтение. Индексатор это свойство с параметром `this[int]`.

**Исключения**
- Порядок `catch` от частных к общим. `finally` выполняется всегда. `throw;` сохраняет стек ошибки.

**Прочее**
- `static` принадлежит классу. `readonly` присваивается только в конструкторе. `==` для ссылочных типов сравнивает ссылки, если не перегружен, `Equals` сравнивает по значению, если переопределен.
- `ArrayList` хранит `object`, `List<T>` типизирован и безопаснее.
- Финализатор вызывает сборщик мусора неизвестно когда. `IDisposable` вместе с `using` дает точное освобождение.
